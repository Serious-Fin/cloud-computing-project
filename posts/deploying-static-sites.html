Deploying a static site to Netlify

A static site is just files: HTML, CSS, JavaScript, images. There is no application server deciding what to send back. The host stores the files and hands them out. That simplicity is the whole appeal.

Two ways to get files online

Netlify accepts a site in one of two shapes, and both end up in the same place — a folder served from a global CDN.

  1. Drag and drop. Open the Netlify dashboard and drop your project folder onto the deploy area. It uploads the files and gives you a URL within seconds.
  2. Connect a Git repository. Point Netlify at GitHub, GitLab or Bitbucket. Every push to your default branch publishes the site, and every pull request gets its own preview URL.

The second option is worth the extra setup because you never have to remember to upload anything again.

The only two settings that matter

When you connect a repository, Netlify asks for a build command and a publish directory. For plain HTML there is nothing to build, so you can leave the command empty and point the publish directory at the folder holding your index.html. 

# For this exact project:
Build command:     (leave blank)
Publish directory: .

If your HTML lives in a subfolder such as public/ or dist/, use that instead. Netlify looks for an index.html inside the publish directory and serves it for the root URL.

Did I misspell the file name?

File names on the web are case sensitive. A link to Posts.html will not find posts.html. This is the single most common static-site bug, and it is invisible on macOS because the default file system is case insensitive.

If a page works locally but 404s once deployed, check the capitalisation of the file name before anything else.

Why bother with static at all?

  • Nothing to patch, because there is no server process.
  • Fast by default — files sit on edge servers close to the visitor.
  • Cheap or free, since serving bytes is much cheaper than running code.
  • Trivially portable. Any host that can serve a folder can serve this site.

The trade-off is that anything dynamic — logins, a database, form submissions — needs another service. For a blog, a portfolio, or documentation, that trade is usually a good one.

Undoing a bad deploy

Every deploy Netlify makes is kept. If a change breaks the site, open the Deploys tab, pick the last good one, and publish it. Rollback takes about ten seconds and requires no rebuild.
